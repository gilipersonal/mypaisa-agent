5. Data layer

5.1 Price sources: one plugin per feed, a chain per kind, chosen by configuration

Every feed is a plugin behind one small contract, and which plugins run, in which order, is configuration per environment. Yahoo Finance (yfinance, free, no key) is the default everywhere and the only feed local development needs. Switching to EODHD is a setting plus a key in SSM, not a code change, and it is a last resort: free sources first (yfinance, Twelve Data's free tier, free websites where their terms allow), EODHD only when the data steward shows a free source cannot serve a holding and the admin approves (§20.3).

The contract. A plugin implements:

class PriceSource(Protocol):
    name: str                                   # "yfinance" · "eodhd" · "twelvedata" · "issuer_page" · "ft" · "proxy" · "screenshot"
    def supports(self, instrument: Instrument) -> bool: ...
    def daily_bars(self, instrument: Instrument, since: date) -> Bars: ...   # native currency, with source, fetched_at, provisional
    def latest(self, instrument: Instrument) -> Quote | None: ...
    def fx(self, pair: str, since: date) -> Rates | None: ...                 # optional

Each plugin owns its own identifiers on the instrument (identifiers holds the Yahoo symbol, the EODHD code, the Twelve Data symbol and the ISIN side by side), its key in SSM (/mypaisa-agent/<env>/<plugin>/api_key), its rate limit, its GBX-to-GBP normalisation, its freshness rule, and its recorded fixtures. The ingest job sees only Bars, never a vendor shape. A plugin that is not in any chain is never imported, so a missing key is not an error.

Chains by configuration. The chain per kind lives in each environment's Terraform root (infra/dev/terraform.tfvars, infra/prod/terraform.tfvars) and reaches the Lambdas as one environment variable, with a per-instrument override in Instrument.price_sources[] for the odd case:

# infra/dev/terraform.tfvars (local uses the same shape from a .env file)
price_chains = {
  oeic      = ["yfinance", "issuer_page", "ft", "proxy", "screenshot"]
  lse_etf   = ["yfinance", "twelvedata", "issuer_page", "stale"]
  us_etf    = ["twelvedata", "yfinance", "stale"]
  cash      = ["ecb", "twelvedata"]
}
# infra/prod/terraform.tfvars, once EODHD is chosen: put it first and add its key
#   lse_etf = ["eodhd", "yfinance", "twelvedata", "issuer_page", "stale"]
#   us_etf  = ["twelvedata", "eodhd", "yfinance", "stale"]

The first plugin that answers with fresh data wins, and the brief says which one did. stale is the last entry everywhere: the previous close, labelled, never silently reused.

Proving a plugin. Every plugin passes the same contract test suite on recorded responses: the same instrument and date range give the same Bars shape, pounds not pence, the stale rule, idempotence per date, and a clean failure when the vendor is down. Tests never touch the network; a deliberate command refreshes the recordings. When two plugins are configured for the same instrument the ingest job records both, and the Activity page (§9.3) shows where they disagree (a close more than 0.2% apart, a missing day, a late correction). That report is how the "free first, EODHD if London closes prove unreliable" decision of phase 10 is made with numbers rather than impressions.

Twelve Data's free tier (8 credits a minute, 800 a day) is used for everything it serves: first in the chain for the US lines, the US macro basket, the earnings calendar and the FX fallback, and second for London and Frankfurt closes from day one. Whether the free tier actually returns LSE and Xetra bars is not known; the chain simply skips a plugin that answers nothing, and the source-comparison report shows what it served. If it does serve them, EODHD is unnecessary. The daily credit budget is enforced in the plugin: the ingest job spends at most 200 a day, so the agent's own calls (symbol search, the earnings calendar on demand) never run the tier dry.

Input hygiene, from the desk: drop interpolated bars, append today's close only when the session has traded, mark a series STALE when its last bar is older than the previous session and exclude it from scoring (the circuit breaker). Every job is idempotent per date.

5.2 Look-through

From the factsheet (and later the product page): asset allocation, top holdings, regional and currency split. It drives three things: the proxy basket for a fund's intraday read, the currency split of each move, and the overlap review across holdings. Refreshed when a new factsheet is uploaded or monthly from the page.

5.3 FX, calendars, time

GBP base; USD, EUR and INR, all published daily by the ECB. Each member can read every figure in any of four currencies, GBP, INR, USD or EUR (Arun, 29 Oct 2026, MA-275: "The app should support 4 currencies"); the stored value is always both the native amount and its GBP equivalent on the day, and a rupee figure is grouped in lakh and crore. The household's records are in the UK and India today; a record in the US or the euro area is added the same way when one is needed: a country is data (its kinds, its inflation and wage-growth priors, §6.6), not code. Money typed in one currency for a holding in another is checked and converted as in §4.7. Exchange calendars XLON, XETR, XNYS. All schedules in Europe/London.

6. The analysis engine (deterministic, ported from the desk)

6.1 Indicators

EMA 20/50/200 (SMA seed), Wilder RSI-14, MACD 12/26/9 with histogram slope, TRIX-15 with EMA-9 signal, Bollinger 20/2 with %B, slopes vs 5 bars, bars_since_below_ema20; plus ATR-14, realised volatility (20-day and EWMA) and its 3-year percentile, drawdown from the 1-year high, 12-1 momentum, proxy-vs-NAV gap. The desk's known-answer self-tests become golden-file tests and also run at the start of every engine run; a failing self-test blocks scoring that day and tells you.

6.3 The holder's cascade

The desk's cascade rotates capital; ours accumulates with care. holding is always true for a position and false for a watchlist item.

ActionWhenFraming
ADD, shown as BuyHolding; trend ≥ 0 and momentum ≥ 0, or a rebound with healthy structure after a drawdown; risk not elevatedBuy more: make this month's contribution here, or bring it forward
HOLDDefault for a holding with no triggersNothing to do
PAUSEHolding; exhaustion ≥ 2 or risk elevated or adverse macroKeep what you have; delay new money until the next review
TRIMHolding; drift above target by more than the band, or relentless-bearish ≥ 3 with a death-cross, and the position is not protectedRebalance toward target; never "sell everything"
REBALANCEPortfolio-level drift beyond the bandMove the next contributions, not the holdings, unless drift is large
BUYNot holding; a candidate on the watchlist whose entry trigger is met: trend ≥ 0 and momentum ≥ 0, risk not elevated, data not staleStart a position with new money, from the next contribution; never by selling another holding
WAIT / WATCHNot holding; a candidate with no entry trigger yetThe trigger that would change it to BUY

Every card says Buy for ADD and for BUY, so the household reads one word for buying (Arun, 29 Oct 2026, MA-275: signals "like hold, buy"); TRIM is the only call that sells, and only part, and nothing ever says "sell everything". A candidate is put on the watchlist from the chat ("watch the S&P 500 ETF"), a record with holding false, and is scored like a holding.

Adverse macro and elevated risk tighten the framing and lower confidence; they never change the pillar numbers. Sentiment may tilt the action one notch only when the price pillars do not contradict it. News alone never triggers a red alert.

6.4 Confidence score

confidence = clamp(0.5 + agreement + persistence + quality + history, 0, 0.95)

  • agreement: pillars pointing the same way (+0.05 each, −0.05 each against)
  • persistence: bars the state has held (0 for 1 bar, up to +0.10 for 10+)
  • quality: −0.10 if partial components, stale or provisional data, or a proxy gap over 1%
  • history: the empirical hit-rate of past stances in the same state bucket, once 20 or more exist, pulling the score toward it

Shown as a percentage; below 55% the card says "no clear view". Calibrated weekly (Brier score, reliability table by bucket); the mapping changes only after 8 weeks of evidence and the change is logged. From phase 18 the learning loop grades every day and moves the map daily within small bounds, with an automatic rollback; changes to the rules themselves still need evidence and the admin's approval (§20.4).

6.5 Forecast ranges

1-month return distribution by volatility-scaled block bootstrap on the instrument's own history: 10/50/90th percentiles and P(fall > 5%).
