🌐 The system, at a glance

📜 Before section 1: what MyPaisa is

ARCHITECTURE.md's opening, as written.

A private analyst and wealth keeper for one household, used by someone who is not a finance person, through one chat at every door: the iOS app on the household's iPhones and iPads, and the web app in any browser, at desktop and phone width. The chat registers and keeps everything the household owns and owes in the UK and India, asks on its own when something is due, computes what moved and why, takes a stance with a confidence score, explains it plainly, goes technical on request, asks before it acts, and grades itself. Beside the chat, at both doors, the dashboard shows the household's whole wealth: net worth, assets, debts, the budget, the Projection, the audit log of every change, and a record of what the agent did and spent. Anything new is created in the chat; an existing figure can be corrected in place where it shows (§1, rule 4). Members sign in with Apple or Google, or a passkey on the web. It runs on AWS in account 545595341442, us-east-1, with Claude through the Anthropic API. It never trades.

v4 (MA-186, 26 Oct 2026) puts the household's whole wealth first, built together with the agentic setup, layer by layer, at both doors in every phase (PLAN's phases 0 to 9; the market side follows in phases 10 to 20). The old wealth tracker and MyPaisa become one product: one dashboard of everything the family owns and owes in the UK and India, each member's assets and debts, a budget from statements and monthly check-ins, and a Projection the AI drives and code computes. The chat registers and maintains everything, with no forms, and asks on its own ("was this month's EMI paid?"). Arun: "Keep the entire structure dynamic. This is not a traditional transaction SQL structure"; "The UI should only allow editing existing figures by hand, no creation"; and, for the app, "Performance is key … silky smooth like Monzo". So kinds are data, records are documents and their history is events (§4.8); commitments and check-ins replace the one-off reminders (§4.9); anything new is created in the chat and a figure is corrected in place, through one write service (§4.10); the web app is a full door with the chat, a SvelteKit 3 PWA at dashboard(-dev).mypaisapp.com (§9.4); the iOS app is a React Native shell with a native SwiftUI core (§9.5); live delivery is SSE on the api host (§21.5); and the Projection is computed by code from priors and the household's own history (§6.6). v4 keeps v3's Warm ledger on Liquid Glass, its sign-in and its Admin center; it supersedes v3's read-only dashboard, the web app without the chat, the app built in SwiftUI alone, the console and live hosts and the WebSocket. The old tracker holds no real data: its tested maths and its screens are ported, not imported (§12).

v3 (MA-161, 25 Oct 2026) moves the chat from a Telegram bot to one native SwiftUI app for iOS and iPadOS 26, in Warm ledger on Liquid Glass (§9), and keeps the web app for the read-only dashboard and the Admin center (§9.4). Arun: "redesign everything from Telegram to iOS app. No more telegram login ... make the app into a cool mobile chatbot where they can maintain everything and even see the dashboard of the holdings in the household. Only iOS app is needed and nothing else for now." And, the same evening: "we have webapp for the dashboard and admin portal pwa ... That will still be there for the read only dashboard"; "The read only dashboard should also be shown on the ios tablet duo." Everything behind the front door (the registry, the audit log, the queues, the engine, the cards, the budgets, the Forecaster, the agent team, India) stands as v2 drew it. v2 folded in what docs/RESEARCH.md found in the Agentic Trading Desk and Agent Toolbelt: the desk's deterministic indicator and pillar engine and its discipline, the toolbelt's card shapes and portfolio review, and the layman's front end both of them lack. v1 (prices, briefs, alerts, chat, news, calls on Lambda) stands underneath; sections that have not changed are kept short.
