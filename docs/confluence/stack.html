How the FastAPI REST APIs (handlers/api and handlers/stream) fit into the trace and request-ID flow (MA-266)

Both HTTP entry points on api(-dev).mypaisapp.com run FastAPI (MA-266):

  1. handlers/api (buffered REST routes): FastAPI wrapped in Mangum(app, lifespan="off") behind API Gateway REST API proxy integration (POST /v1/chat/messages, POST /v1/chat/actions, GET /v1/chat/turns, GET /v1/records, PATCH /v1/records/{id}, POST /v1/uploads, POST /v1/telemetry, /v1/admin/*, /v1/auth/*). Mangum translates the API Gateway REST event into an ASGI scope in-process with zero sidecar overhead, keeping cold start under 300 ms (MA-232).

  3. scripts/local/ (laptop dev server, MA-198): Mounts both FastAPI routers into a single local Uvicorn ASGI process backed by moto.

    • Each anthropic SDK streaming call opens a CLIENT span chat claude-sonnet-4-6 (or chat claude-opus-4-7 / chat claude-haiku-4-5) with OpenTelemetry GenAI attributes: gen_ai.operation.name="chat", gen_ai.provider.name="anthropic", gen_ai.request.model, gen_ai.response.model, gen_ai.response.id (Anthropic's msg_...), gen_ai.response.finish_reasons, gen_ai.usage.input_tokens, gen_ai.usage.output_tokens, gen_ai.usage.cache_read.input_tokens, gen_ai.usage.cache_creation.input_tokens, plus mypaisa.agent, mypaisa.run_id, mypaisa.spend_step, mypaisa.time_to_first_token_ms, mypaisa.cost_usd, mypaisa.prompt_version, mypaisa.fallback_from, and mypaisa.refused.

    • a short GET /v1/stream handshake span (authorizer check, Last-Event-ID / ?after= catch-up query on DynamoDB, and initial TurnBuffer flush, typically < 40 ms); and
    • a stream.deliver child span per delivered StreamEvent, linked to the originating turn's trace_id and run_id, flushed immediately through the Lambda OpenTelemetry collector extension.

6.3 Agent frameworks: options, trade-offs & recommendation (MA-265)

What MyPaisa's agent layer requires (ARCHITECTURE.md §7, §18, §21)

Any agent runtime we choose must satisfy ten hard architectural constraints already settled in ARCHITECTURE.md:

  1. Direct Anthropic API (api.anthropic.com) so development and evals draw from Arun's Claude Max 20x Console credit and production uses features Bedrock lags on (ARCHITECTURE.md §7, docs/RESEARCH.md §4.1).
  2. Explicit cache_control breakpoints (ephemeral; at most three, the chat's fixed part on the 1h TTL, with the request's automatic caching for the tail and a lifetime per route, ARCHITECTURE.md §22.1, MA-286) on the stable system prompt, tool definitions, household profile, and Kind catalog so multi-turn conversations and 15-minute jobs achieve > 60% cache-read hit rates (§22.1).
  3. Claude 5.5 thinking blocks & cryptographic signatures preserved verbatim and append-only across tool-use turns within a run (§7).
  4. Constrained decoding (strict: true) on every tool schema + isolated server-side web_search_20260209 / web_fetch_20260209 inside dedicated tool-less search_web / fetch_page sub-calls so untrusted web content never shares an API request with household write tools (§21.2, lesson 32).
  5. Anthropic Message Batches API (50% discount) for overnight non-urgent workloads (narrator prose, archivist conversation notes, and the 3 LLM judges in MA-252).
  6. Deterministic pre-tool PolicyGate in Python (§21.2) checking five invariants (manifest allowlist, member role, household partition, schema/date bounds, per-run caps + untrusted-content taint narrowing) before any tool executes, and FigureCheck (§21.2, MA-248) checking every number in the final reply against tool outputs before sending.
  7. Stateless pause & resume across hours (PendingAction, §7): When the agent calls ask_user or proposes a Confirm card (draft_record, propose_plan_item, propose_budget_rearrangement), the Lambda must not block waiting for a human; it writes a PendingAction row to DynamoDB and exits cleanly, and the next SQS message hours later resumes from that state.
  8. OpenTelemetry GenAI spans (gen_ai.* + mypaisa.*) and RunRecord (§9.1, §9.3) with exact per-call cache-read/write tokens, TTFT, stop reason, and cost.
  9. Inspect AI (T0 deterministic replay + T1 golden set + T2 full suite, §21.3, MA-246) replaying recorded conversations with zero network in CI.
  10. Phase 13 agent team (§18; nine agents as of MA-265, before MA-307 retired the market side): Only two agents (concierge and research) run an open-ended LLM tool loop; four (ingestion, planner, sentinel, narrator) are deterministic Python pipelines that call Claude once for structured extraction or prose; and three (market_data, quant, archivist) are 100% deterministic Python with zero LLM calls, orchestrated by AWS Step Functions and Amazon EventBridge (mypaisa-<env>-events), each in its own Lambda with its own IAM role.

Recommendation (MA-265)

We recommend Option 1: a thin, explicit ~300-line Python agent loop (AnthropicAgentRunner, MA-271) built directly on the official anthropic Python SDK + Pydantic v2, orchestrated across agents by AWS Step Functions and Amazon EventBridge (ARCHITECTURE.md §7 & §18), while adopting PydanticAI's typed RunContext[Deps] decorator pattern for our tool definitions (backend/src/mypaisa_agent/agent/tools.py).

Why this combination gives MyPaisa the best of both worlds:

  1. Zero abstraction tax on Claude features: We pass raw Anthropic content blocks (text, thinking with signature, tool_use, tool_result, document PDF blocks, and cache_control={"type": "ephemeral", "ttl": "1h"}) directly to anthropic.Anthropic().messages.stream(...) and client.messages.batches.create(...).
  2. FastAPI-grade developer ergonomics for tools (borrowed from PydanticAI): Every tool is a Python function decorated with @tool(name="...", read_only=True, agents=("concierge",)) whose arguments are a Pydantic v2 BaseModel, exported to Anthropic with strict: true JSON Schema (anthropic.transform_schema(Model)), and receiving a typed RunContext (household_id, member_id, role, registry, tracer, tainted).
  3. Deterministic guardrails sit directly in the loop (§21.2): ``` stream Claude turn -> append thinking & text deltas to TurnBuffer (SSE) -> if stop_reason == "tool_use": for each tool_use block:
    1. PolicyGate.check(ctx, tool_name, tool_input) # 5 deterministic rules + taint check
    2. if tool is ask_user or draft_*/propose_*: save PendingAction to DynamoDB -> emit CardEvent -> exit Lambda cleanly
    3. execute typed Python tool under OTel span "tool <name>" loop (at most eight model calls a run, ARCHITECTURE §14.1) -> when stop_reason == "end_turn": FigureCheck.verify(reply_text, tool_results, user_words) write RunRecord + Conversation turn -> enqueue to outbox.fifo ```
  4. Hardware-grade multi-agent isolation in Phase 13: Instead of an in-memory multi-agent framework (CrewAI / LangGraph) where all agents share one IAM role and chat in prose, Phase 13 uses AWS Step Functions (for the daily run) and Amazon EventBridge (mypaisa-<env>-events) (for reactive events), with each agent running in its own Lambda under its own least-privilege IAM role (§18.2).
