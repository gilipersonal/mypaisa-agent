🧭 MyPaisa Agent Journey

26 Oct 2026 · MA-141, India added in MA-155, the iOS app in MA-161, re-phased in MA-186, the whole wealth's flows in MA-226 · design only, nothing is built yet

How a household uses MyPaisa, one flow at a time: what the member does in the MyPaisa app on an iPhone or an iPad, or in the web app in a browser, the path it takes through the app, AWS and Claude, what the member sees, and what keeps it safe. The app is a chat where the household keeps every record, with the dashboard of its holdings one tap away; the web app has the same chat and dashboard, and the owner's Admin center, in a browser on a laptop or a phone. The UK holdings come first; the household's Indian funds, shares and ETFs join them in rupees, with pounds beside every figure. Each flow names the Jira stories that build it.

Every figure, rate and fund name on this page is illustrative. "You" are Arun, the household's owner; Asha is the second member. 📏 Four rules every flow keeps

From ARCHITECTURE.md §1. Each path below shows where they bite.

Rule 1

Claude never produces a number

Every figure comes from code with tests. Claude chooses what to say and how to say it.

Rule 2

The app cannot trade

No broker login, no orders. MyPaisa suggests only actions that suit the account: ISA-safe for the UK wrappers, wrapper-aware for Indian accounts.

Rule 3

Summary first, detail on tap

Every message and every card has a plain top and a technical underside. Nothing technical is shown unasked.

Rule 4

Create in the chat, correct in place

Anything new is created only in the chat: a card, a Confirm tap, an audit row. An existing figure that its kind marks editable can be corrected in place on any screen, at either door. Both go through one write service, which writes the audit row. The one exception is the owner's Admin center, in the app or the web app, which acts on admin settings and operations, never on a record, each behind the second check and an audit row. Arun, 24 Oct 2026: "Dashboard will be read only (except for admin)"; widened on 26 Oct 2026 (MA-186): "The UI should only allow editing existing figures by hand, no creation."

📖 How to read a flow

Each path is a numbered sequence across five lanes. An arrow is a hand-off from one lane to another; a box is work done inside one lane. Safeguards are underlined in coral. On a narrow screen the same steps stack, each tagged with its lanes.

Member

You or Asha, in the MyPaisa app on an iPhone or an iPad (or a foldable, folded or open), or in the web app in a browser on a laptop.

App and web app

MyPaisa, one app for iPhone and iPad on iOS 26, a React Native shell with a native SwiftUI core: the chat with its cards, composer and shortcut chips; Home, Activity and You; the Admin center for the owner; the Keychain, Face ID, push and the share sheet. It talks to AWS over HTTPS (api.mypaisapp.com), and replies stream to it over Server-Sent Events from the same host. Beside it, the web app at dashboard.mypaisapp.com: a SvelteKit 3 progressive web app with the same chat, the dashboard and the Admin center.

AWS

API Gateway (the api's REST API, with the SSE stream as its streaming route on the same host), the api λ, the SQS FIFO updates queue, the agent λ, the SQS work queue and worker λ, the SQS outbox and sender λ, DynamoDB, S3, Cognito, EventBridge Scheduler, Step Functions (phase 18), SNS, CloudWatch.

Claude

The Anthropic API: Haiku, Sonnet and Opus 5.5, server-side web search and fetch, Message Batches.

External data

Free sources first: yfinance, Twelve Data's free tier, ECB FX, issuer pages, FT, RSS. For India: AMFI's NAV file from phase 5; from phase 19, mfapi.in, yfinance .NS and .BO, NSE and BSE bhavcopy, the RBI/FBIL rate, Indian news feeds. Apple and Google, when they vouch for a sign-in; Apple's push service (APNs), when the app is closed.

🛡️ The safeguards, in one place

They recur across the flows, so here is what each one means.

Confirm before any write

Anything new is shown as a card first and saved only after the member taps Confirm on it; a check-in's Paid is the Confirm of a card that shows exactly what it saves. A correction in place shows its before and after, then Save. A change across several records is one plan with one Confirm.

The audit row

An AuditEvent in the same DynamoDB transaction as the change: who, when, through what, before and after, which run. Hash-chained, never deleted.

Privacy mode

The eye on Home and in You, or /privacy, hides pounds and rupees in every card, screen, chart axis and notification; percentages stay, and the app switcher shows only the mark (MA-171). On the currency check's cards (MA-156, ARCHITECTURE §4.7) it shows no amount and no rate, only words, currencies and dates.

The currency check

Every holding keeps the one currency it is bought and valued in. An amount typed in another is never saved as it is: MyPaisa says why and asks for the amount that arrived (MA-156).

Signed in, in the app or the browser

Sign in with Apple or Google (or, in the browser, a passkey), exchanged for Cognito tokens: in the app they live in the Keychain, this device only; in the web app behind an HttpOnly cookie page scripts never see. Five-minute access tokens; token, status and session epoch checked on every call and on the stream.

The second check

In the app, a fresh Sign in with Apple or a passkey under Face ID (a Google-only member signs in with Google again); in the web app, a passkey or a fresh sign-in. Bound to one action and verified by the server: an import, a rollback, leaving the household, and every admin action, from the Admin center or the admin's chat, approving a new kind among them (MA-197). A local Face ID alone never authorises anything.

The spend ladder

The month's Claude spend is read before every call; at 70, 85, 95 and 100% of the ceiling MyPaisa steps down. Alerts are never dropped.

Retries and dead-letter queues

Every hand-off goes through SQS: retried with backoff, idempotent, and kept in a dead-letter queue with an alarm and a replay when it keeps failing. The app keeps what is typed offline and catches up when it opens.
