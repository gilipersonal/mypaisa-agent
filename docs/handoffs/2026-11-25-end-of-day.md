## Lessons from today (also in Claude's memory)

- **The jira-flow guard reads the main checkout's branch, not the worktree a command `cd`s into.**
  - Once a merge leaves the main checkout on `main`, the guard refuses a push or `gh pr create` from a worktree.
  - Use `git -C <worktree> push`.
  - Raise the PR from the main checkout, with the branch checked out there.
- **The PR hook runs `plan_sync.py check` before the whole command starts.** Record the pages (`set-page`, `set-readback`) in one command, and run `gh pr create` in the next.
- **A preview is not re-uploaded when it comes out byte-identical.** A note outside a board's captured frames changes no picture. Re-record the live media id with `set-image` instead.
- **A same-named attachment re-upload changes the live page's media id with no new page version.** A page whose only change is a preview needs a read-back, not a send.

## Rules that bite (short list)

- Ship autopilot:
  - Branch `MA-<n>-<slug>`, commit `MA-<n>: ...`, PR `[MA-<n>] ...`.
  - Merge commits are `MA-<n>: Merge PR #<n>: <title>`.
- **Plan-sync and the security scan run only on Arun's yes,** asked once at the end of the work, together with the PR and merge question and the offer of a review and QA.
- Never merge with any check pending.
- Boards go to `ios-v1/`, `app-v1/` and `ds-v1/` only, never Prototype v5. A picked board is the spec: change the board first, then the code.
- Confluence is generated from the repo and published with read-backs. Never edit it there.
- Stubbed stories go back to In Progress after their merge, not Done.
