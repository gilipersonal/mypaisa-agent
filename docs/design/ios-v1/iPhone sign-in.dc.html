SSigning in, joining and the first run on iPhone

How a member gets into MyPaisa on iPhone (MA-168): Apple's and Google's own buttons and nothing else, an invite link that opens the app to join, the three setup questions as the first conversation, then notifications and an optional Face ID lock. There are no passwords. Sheets and alerts that iOS or Google draw are labelled as theirs; everything else is Warm ledger content under option 1a's Liquid Glass controls. Each board is drawn in light and dark; a board with several steps shows them side by side, and each frame plays its motion as it scrolls into view (replay beside its label). Illustrative figures and names.

iOS draws this sheet. MyPaisa calls ASAuthorizationAppleIDProvider with no scopes, so iOS asks for no name and no email: just the account, Face ID and Continue.

Bound to this sign-in. The api hands the app a one-time nonce first; Apple's identity token carries its SHA-256, and the verify Lambda checks issuer, audience (the bundle id), expiry, an issue time under five minutes, the nonce and no replay (MA-109).

Then the Keychain. The app exchanges the token at /auth/apple for the member's Cognito tokens, kept on this device only after first unlock; the five-minute access token refreshes quietly and the refresh token rotates (MA-168).

Close leaves the welcome as it was; nothing is sent.

Setup is the first conversation. Three questions as cards, one at a time, in option 1a's chat; each answered card folds to one line above, with Change.

1 · Base currency: £ GBP, ₹ INR or Other (a list). Totals are shown in it; each holding keeps its own currency (§4.7). 2 · What you hold: send a factsheet or a screenshot (the + gives the camera, a scan, Photos and Files) or type it; Later skips. Each holding then comes as a card to Confirm (rule 4).

3 · How often: mornings and alerts (the 07:15 brief), only alerts, or weekly. It can be changed later in You › Notifications.

Still open for MA-35's options round: the answers are saved as they are given, as on the Telegram board; whether setup needs a Confirm is that round's question. Keys MA-35, MA-168.

MyPaisa asks first, in its own words. The card says what will arrive and that amounts stay off the lock screen. Only Turn on notifications brings iOS's alert, so Not now saves iOS's one question for later (You › Notifications).

iOS's alert is iOS's. Allow registers this iPhone's push token with the api (POST /v1/devices). The 07:15 brief and the 21:15 wrap are ordinary notifications; a red alert is time-sensitive with sound (MA-170).

No amounts on the lock screen unless the member turns on Show amounts in notifications, and never with privacy mode on.

The Face ID lock is a comfort, not a check. Face ID or the passcode on opening and after five minutes away, on this iPhone only (MA-171); iOS asks once to allow Face ID. It never approves anything on the server: that is the second check (MA-76). Keys MA-170, MA-171.

Kind, plain, no codes. Each screen says what happened and what to do next in a sentence or two; none names the check that failed. Nothing here is red: no action is asked for.

a · Linked to nobody, no invite. Once a household exists MyPaisa is by invite only, so the way in is an invite from the household's owner.

b · Removed: told once, with what is kept. c · Paused: one line and nothing else (MA-102), until the owner restores them from the Admin center.

d · The invite: links last 24 hours and work once; a used one reads “This invite has already been used. Ask the person who sent it for a new one.” Keys MA-168, MA-102.
