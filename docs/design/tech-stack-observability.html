1 · End-to-end tracing and Request ID propagation

One trace and every correlation ID from the tap through FastAPI, SQS and Claude to the stream

When you send a message or tap Confirm on your phone or laptop, the app stamps it with a unique trace number and a message ID. As that message travels through the front-door FastAPI server, the waiting queues, the agent talking to Claude, and the live reply stream back to your screen, every step passes that same trace number along.

Every response also hands the trace number and request ID back to your device in its headers, so if anything ever goes wrong, one click in the Activity screen opens the entire journey in AWS CloudWatch — while a strict automated test guarantees no personal figure, name or message text is ever written into the logs.

Already planned in ARCHITECTURE.md §9 (MA-29, MA-230 to MA-236, MA-196) and extended with FastAPI in MA-265 and MA-266: both doors generate a W3C traceparent (00-<trace_id>-<span_id>-01) and client_message_id (ULID). handlers/api runs FastAPI behind Mangum(app, lifespan="off"); handlers/stream runs FastAPI on Uvicorn behind the AWS Lambda Web Adapter 1.1 (AWS_LWA_INVOKE_MODE=response_stream).

CorrelationMiddleware and opentelemetry-instrumentation-fastapi run on both apps: they extract traceparent, read API Gateway's request_id (aws_request_id / x-request-id), bind {trace_id, span_id, request_id, client_message_id, run_id, household_id, member_id} onto the Powertools Logger and the active span (setting http.route for Application Signals), and echo x-mypaisa-trace-id and x-request-id on every HTTP response and SSE handshake. Across updates.fifo, outbox.fifo and work, the AWS OpenTelemetry distro propagates AWSTraceHeader automatically and handler code copies traceparent, request_id and run_id into SQS message attributes.

2 · Observability surfaces and monthly costing

Three readers for every run, for £0.03 a month in dev and £2.46 a month in prod

You never have to open the AWS console just to see what MyPaisa did or what it cost. Every run is written into the app's own Activity screen with its steps, tools, tokens and cost. When you want engineering curves, an eight-panel CloudWatch dashboard and full trace search are ready in AWS; when something breaks or spend crosses 70%, MyPaisa messages you in the chat and by push.

By writing our own metrics in CloudWatch's Embedded Metric Format and sending 100% of spans to CloudWatch Transaction Search instead of paying per-trace X-Ray fees or $39+/month SaaS seats, the entire observability stack costs £0.03/month in dev and £2.46/month in prod.

infra/modules/mypaisa/observability.tf (MA-231) provisions all log groups (30-day retention in prod, 7-day in dev, 365-day for evals), aws_xray_transaction_search_config (100% of spans into aws/spans, no $5/M X-Ray Indexed Spans charge), Application Signals on FastAPI's http.route spans, the 8-panel CloudWatch dashboard, 7 saved Logs Insights queries, 15 EMF metrics in MyPaisa/Agent (billed as log bytes, $0 per metric), and 12 alarms per environment (first 10 across the account free).

3 · Front-end tech stack (`web/`)

SvelteKit 3.1, Svelte 5 runes, Tailwind CSS 4, shadcn-svelte and TanStack

The web app at dashboard.mypaisapp.com works on a laptop, an iPad or a phone browser. It uses SvelteKit 3 with Tailwind CSS 4 in the Warm ledger look, accessible components from shadcn-svelte, and TanStack for live data, sortable tables, long virtualised audit lists and inline figure edits.

Its data types are generated automatically from the Python FastAPI server, and the iOS app imports that exact same TypeScript folder so the browser and the iPhone can never drift apart.

Proven in Smart Clearance (`MA-194`, `MA-229`, `MA-265`): a pnpm 12.x workspace on SvelteKit 3.1.x (@sveltejs/adapter-static) and Svelte 5.57.x runes ($state, $derived, $effect), built with Vite 8.x and TypeScript 6.x. Styled with Tailwind CSS 4.3.x over docs/design/ds-v1/tokens.css, shadcn-svelte 1.7.x on bits-ui 2.20.x, LayerChart 2.9.x + d3-scale / d3-shape for wealth charts, and Motion 14.0.x.

Data and state run on @tanstack/svelte-query 6.3.x (updated in place by the SSE stream on records.changed), @tanstack/table-core 9.3.x, @tanstack/svelte-virtual 3.13.x and @tanstack/svelte-form 1.33.x + zod 4.x. pnpm --dir web api:types runs openapi-typescript 7.x against FastAPI's app.openapi() to emit web/src/lib/api-types.d.ts.

4 · iOS tech stack (`ios/`)

React Native 0.88 TypeScript shell + Swift 6 SwiftUI core at 120 Hz ProMotion

The iPhone and iPad app uses React Native 0.88 for the invisible plumbing — signing in, caching data offline, listening to the live SSE stream and sharing the TypeScript logic with the web app — while every screen, card, chart and Liquid Glass control you see and touch is built in native Apple SwiftUI running at 120 frames per second.

Built on the pattern proven in bong-panjika (`MA-165`, `MA-229`, `MA-265`): bare React Native 0.88.x (New Architecture, Fabric + TurboModules, Hermes, React 19.3, TypeScript 6, no Expo), with native dependencies managed exclusively via Swift Package Manager (never CocoaPods). The shell runs @tanstack/react-query 5.105.x over #lib, react-native-mmkv 4.3.x on react-native-nitro-modules 0.14.x (encrypted via Keychain), and react-native-reanimated 4.7.x + react-native-gesture-handler 2.32.x.

Each screen or card crosses the synchronous C++ Fabric bridge as one pre-formatted JSON view model into a UIHostingController running Swift 6.x (strict concurrency) on iOS and iPadOS 26: 1a Chat-first adaptive shell, native Swift Charts at 120 Hz with .sensoryFeedback, and Liquid Glass (.glassEffect()) on floating controls only.

5 · Python 3.14 backend, FastAPI & DynamoDB vs DocumentDB

FastAPI on Mangum and Uvicorn + LWA, and a typed single-table DynamoDB repository with no DocumentDB

Are we doing DocumentDB? No. Even though MyPaisa's records are flexible documents ("kinds are data"), Amazon DocumentDB is an instance-based cluster that costs £75 to £110 a month just to sit idle across dev and prod, plus VPC NAT overhead — blowing past the entire £50/month budget before a single Claude call is made. DynamoDB stores nested JSON maps natively inside AWS's permanent free tier (£0.00/month), with atomic multi-row transactions for the hash-chained audit log, while S3 Parquet and DuckDB handle analytical SQL queries in memory for free.

Instead of a heavy ORM like PynamoDB that expects fixed columns, our Python 3.14 backend uses a clean 180-line repository built on Pydantic v2, boto3's native serializer and mypy-boto3-dynamodb for 100% static type checking in pyright.

See docs/RESEARCH.md §6.2 and ARCHITECTURE.md §4.8: backend/src/mypaisa_agent/api/ defines the FastAPI 0.135+ apps for handlers/api.py (Mangum(app, lifespan="off")) and handlers/stream.py (Uvicorn + Lambda Web Adapter 1.1 StreamingResponse). backend/src/mypaisa_agent/registry/repository.py pairs Pydantic v2 (model_dump(mode="json"), model_validate()) with boto3.dynamodb.types.TypeSerializer / TypeDeserializer, boto3-stubs[dynamodb] (mypy-boto3-dynamodb) and a TransactWriteUnit helper wrapping transact_write_items so every Record + Event + hash-chained AuditEvent + view update commits atomically.

6 · Agent framework evaluation and recommendation

A thin custom loop on the official Anthropic SDK, borrowing PydanticAI's `@tool` context pattern

We compared six ways to build MyPaisa's agents: our own thin loop on the official Anthropic SDK, PydanticAI, AWS Strands Agents, LangGraph, the Claude Agent SDK, and CrewAI/AutoGen. Because MyPaisa pauses and exits its AWS Lambda immediately whenever it asks you a question or shows a Confirm card (so you pay $0 while thinking), and because every tool call and every number must pass our own code fences, a thin 300-line loop on the official Anthropic SDK is cleaner, safer and cheaper than any heavy framework.

Recorded in docs/RESEARCH.md §6.3 and ARCHITECTURE.md §7: backend/src/mypaisa_agent/agent.py uses the official anthropic SDK directly so prompt cache breakpoints (cache_control: {"type": "ephemeral", "ttl": "1h"}), adaptive thinking, server-side web_search / web_fetch with citations, Message Batches, and our five deterministic hooks (PolicyGate, FigureCheck, SpendMeter, GenAISpan, stateless PendingAction pause/resume) sit in plain sight with zero framework abstraction tax. From PydanticAI we borrow the typed @tool + RunContext[Deps] registration pattern; in Phase 13, the 6 specialist agents coordinate over AWS Step Functions and EventBridge.
