1 · Local Apple Silicon pool & dual backends (MA-273, MA-198, MA-232)

One Maestro owner per simulator: interactive MCP stays live while cloned CLI simulators run headlessly

Maestro can inspect screens interactively while we build, or run full automated test suites—but if both touch the same iPhone simulator at once, the automated run wipes your login and disconnects the live inspector. So our local runner clones five dedicated background simulators for automated runs and leaves your normal Xcode simulator untouched.

  • Why isolation is mandatory: Every maestro --device <UDID> test CLI run reinstalls maestro-driver-ios (killing any attached maestro MCP XCTest socket) and runs clearState: true. scripts/maestro_local.py setup-pool clones 5 dedicated simulators (MyPaisa-Maestro-iPhone-375, iPhone-402, iPad-834, iPad-1032, iPad-1376 + optional Duo), boots them headlessly via xcrun simctl boot, and guards each UDID with fcntl.flock (/tmp/mypaisa-maestro-<UDID>.lock).
  • Two backend modes: Mode A (--mode stub, default, £0) drives the local FastAPI + moto + T0 recorded Claude SSE server (MYPAISA_API_URL=http://127.0.0.1:8787, compiled inside #if DEBUG only). Mode B (--mode dev-live) runs MyPaisa Dev against api-dev.mypaisapp.com and asserts an unbroken mobile-to-Claude X-Ray trace (MA-232).
2 · Hybrid React Native 0.88 + Swift 6 SwiftUI selector contract (MA-165, MA-273)

One canonical mp.* ID dictionary across Playwright and Maestro, with unmerged SwiftUI card trees

SwiftUI normally bundles an entire card into one lump for screen readers, which hides buttons like Confirm, Cancel, and Technical from automated tests. Our SwiftUI cards keep their children distinct, share the exact same ID names as the web app, and freeze number-rolling animations during functional tests so tests never flake.

  • Shared ID schema: Generates both web/src/lib/test-ids.ts (Playwright) and ios/MyPaisaCore/Testing/TestIDs.swift (React Native testID + SwiftUI .accessibilityIdentifier), checked in L1 CI against every id: in .maestro/flows/*.yaml.
  • Unmerged SwiftUI & Liquid Glass: Every Warm Ledger card and row sets .accessibilityElement(children: .contain) (never .combine); Fabric sets UITabBarItem.accessibilityIdentifier so tabs work even when iOS 26 collapses labels on scroll; Swift Charts expose both AXChartDescriptor and deterministic .accessibilityValue summaries; MYPAISA_STATIC_MOTION=1 settles springs and numericText rolls immediately.
3 · Four-sub-band adaptive width & live rotation matrix (MA-163, MA-240, MA-273)

Testing the chat beside every screen from about 1393 pt, a sheet away from about 600 to 1393 pt, and a tab in a compact window (every iPhone, a folded foldable, Slide Over)

The app adapts strictly by window width: the chat sits beside every screen from about 1393 pt, a sheet away from about 600 to 1393 pt, and a tab in a compact window (every iPhone, a folded foldable, Slide Over). Maestro rotates iPads mid-conversation to prove that moving between a sheet and a side column never drops what you typed.

  • Exact boundary coverage: In addition to the 5 physical device geometries (375, 402, 834, 1032, 1376 pt + Duo), #if DEBUG honours MYPAISA_VIEWPORT_WIDTH at 320 (Display Zoom / Slide Over), 599, 600, 899, 900, 1392 and 1393 pt, guarding the MA-301 rule (the chat beside only from about 1393 pt, which no iPad’s own screen reaches) where three columns would crush the middle screen.

5 · Private 90-day (3-month) TestFlight & evergreen household beta (MA-162, MA-164, MA-167)

Keep MyPaisa installed for 3 months—and rolling indefinitely—with 100% hard-locked privacy

Installing straight from Xcode with a cable expires after 7 days. With the $99/year Apple Developer Program, every TestFlight upload runs untethered on your family's iPhones and iPads for a full 90 days (3 months), updates silently overnight without losing your login or offline cache, renews itself automatically at day 60 so it never expires, and is locked to Internal Testing Only so it can never appear on the public App Store.

  • Hard-locked privacy (testFlightInternalTestingOnly = true): Set in ios/ExportOptions-Internal.plist alongside ITSAppUsesNonExemptEncryption = false in Info.plist. Apple's servers permanently forbid External Testing groups, public invite links and public App Store submission, while skipping Beta App Review (live in 3–5 mins).
  • Least-privilege groups & Double Lock: Individual Developer accounts allow up to 50 additional App Store Connect team users (30 devices each). Family Apple IDs get Customer Support or Marketing scoped strictly to MyPaisa (Household Beta group); MyPaisa Dev stays Arun-only, and the .p8 App Store Connect API key lives in the main-only GitHub dev and prod environments. Inside the app, Cognito + single-use, 24-hour owner-created /join/<token> links enforce a second identity lock.
  • Rolling 90-day evergreen lifecycle (MA-167): TestFlight Automatic Updates install newer CFBundleVersion builds silently in place (preserving Keychain & MMKV) and reset the 90-day clock. At day 60 without an ios/ commit, a keepalive rebuild, archived and uploaded from the laptop (MA-166, MA-167; a scheduled job only alerts), puts a fresh build on TestFlight, backed by a day-60 alert (Phase 0 SNS watch-tower topic, joining §14.2's Admin alert router in Phase 8 MA-137), a client-side MYPAISA_BUILD_EPOCH day-75 Warm Ledger itms-beta:// banner, and Phase 1's GET /v1/app/minimum-version hard update prompt.
