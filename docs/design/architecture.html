MyPaisa Market Agent

One Python agent on AWS Lambda that keeps the record of what you hold, watches it, takes a stance with a confidence score, and talks to you through a private Telegram bot built for a layman. Python does the maths (an engine ported from the Agentic Trading Desk); Claude, through the Anthropic API, explains it, reads your factsheets and screenshots, and answers questions by calling the same code as tools.

  • Markets UK · US · EU

How a message moves through the system

One Lambda does the thinking (agent λ). It wakes two ways: on a schedule, to produce briefs and alerts, and on a webhook, when you message the bot or send it a file. Pick a scenario to watch the request travel.

    Why one agent Lambda and not three

    The brief, the alert and the chat answer all need the same things: your positions, today's signals, your preferences, and the record of what the bot already told you. Putting them in one Lambda with one set of tools means the morning brief and your 3 pm question are answered from the same facts. The webhook Lambda stays tiny on purpose: Telegram resends an update if it waits more than a few seconds, so it verifies the secret_token header, rejects any chat_id that isn't yours, writes the update_id to DynamoDB so a retry is ignored, invokes the agent asynchronously and returns 200.

    How the agent thinks

    Claude never computes a number. Every figure comes back from a tool, and every tool is a Python function the scheduled pipeline also uses. Run the example to see one question answered end to end.

    Model routing keeps the cost down without changing the answer quality where it matters: Haiku 5.5 decides whether an alert is worth a ping and scores news, Sonnet 5.5 writes briefs, cards and chat, Opus 5.5 does the Saturday review. A stance above 70% confidence also gets a two-call bull-versus-bear debate with a judge, a pattern borrowed from TradingAgents.

    The holdings registry: fed from the chat, generic by design

    You add a holding by sending the bot its factsheet and a screenshot of your Monzo valuation, or by typing what it is. Claude reads the PDF and the image, fills a structured card with the source line for each figure and marks anything it is unsure of in amber, and nothing is saved until you tap Confirm. From then on the bot prices it every day. Every holding is an Instrument with a kind, and a kind is a bundle of defaults (price chain, look-through source, how the engine weighs the pillars, how eager the stance is), so a new ETF, a US or UK share, or a commodity adds a row of data, not code.

    Three traps the example writes down. The ISIN is shared by the USD and GBP lines, so the listing is stored separately and the bot asks which line when the factsheet does not say. London GBP lines are often quoted in pence, so the price plugin normalises to pounds and a test guards the 100× error. And every holding here is a dollar asset in a sterling wrapper: one move in GBP/USD moves all of them, so the FX line in the brief is a portfolio-level item and the US macro basket matters far more than the UK one. The exchange calendars (XLON, XETR, XNYS) and ECB reference rates come free; the scheduler runs in Europe/London so the clock-change weeks take care of themselves.

    The engine: pillars, a holder's stance, a confidence you can check

    The maths is ported from the Agentic Trading Desk, a Claude Code skill whose rule is "the scripts perform the deterministic calculations; the model fetches data and talks to the user". Its indicators and pillar scores carry over with their own self-tests as golden files. Its decision cascade does not: it rotates capital for a trading account, and an ISA holder accumulates with care. So the pillars and flags are the desk's; the stance is ours.

    Prediction: news, sentiment and events feeding a call

    Sentiment has a small, real edge over days to a few weeks, mostly around events; it has almost none over a single day, and headlines are priced in within minutes. So the agent does not guess tomorrow's close. It takes a stance with a horizon, a confidence and an invalidation rule, suggests only actions that are safe inside an ISA, and paper-trades every call so the Saturday scorecard can tell you whether the sentiment layer is earning its keep.

    News → sentiment → call, runs every evening
    News arrives all day; scoring runs overnight; the call is made before the UK open and graded when its horizon ends.

    How a score is made

    Each article is scored once by Haiku 5.5 with a strict JSON schema, so the output always parses:

    {
  "instruments": ["monzo-balanced"],
  "direction": -1,            -1 · 0 · +1
  "magnitude": 0.4,           0..1
  "horizon_days": 10,
  "novelty": 0.8,             vs last 7 days of scores
  "event": "BoE MPC minutes",
  "confidence": 0.7,
  "quote": "…will act if inflation…"
}

    The index for a day is the novelty-weighted sum, decayed over the horizon. The call engine only lets sentiment move a stance when the price signals do not contradict it; news alone never triggers a red alert. Everything Claude reads from the web is treated as untrusted text.

    Its own codebase: mypaisa-agent

    A separate repository, its own Terraform state key and its own IAM role. It shares nothing with the wealth tracker at first; later the tracker's backend reads the positions table through a small read-only role. One trap from the tracker's history: the OIDC subject claim embeds the repository's numeric id, so the new repo needs a trust policy with its id, not a copy of the tracker's.

    Rules it inherits

    IAM only in Terraform, deploy by OIDC with a role pinned to this repository's own numeric id, no AWS keys anywhere, the Anthropic API key in SSM with a spend limit. Each function gets a small IAM role: one table, one bucket, its SSM path, its model ARNs. The bot holds no broker login and cannot trade. Nothing is saved without Confirm. Privacy mode hides £ amounts, since bot chats are not end-to-end encrypted.
