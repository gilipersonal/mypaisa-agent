1 · The "One Helper, Four Gates" Playwright fixture (MA-194, MA-181, MA-269)

Every SvelteKit screen passes hard WCAG 2.2 AA rules before Argos captures a single pixel

Instead of scattering accessibility checks and screenshot calls across dozens of test files, every test in web/ calls one shared helper at phone width (390x844) and laptop width (1440x900), in both light and dark themes.

First it freezes motion and waits for fonts. Next it scans the page for accessibility violations using axe-core and checks keyboard focus. If anything breaks a WCAG 2.2 AA rule, the test stops immediately—so a broken screen never wastes your monthly screenshot allowance. Only when the page is clean does Argos capture the screenshot and the accessibility tree.

  • Track A (Board Gates, stopped by MA-303) vs Track B (SvelteKit web/ on Argos CI): The offline gates on the static .dc.html design boards were stopped by MA-303 (Arun, 2 Nov 2026: "I need this checks as QA when I ask, but on actual code implemented"); the QA is measured on the built web app by MA-304, QA on request; iOS QA comes after MA-165, with no story yet. svelte-check, eslint and vitest run on every PR touching web/; Playwright, axe and Argos run only when Arun asks (a manual run or a qa label; MA-303, MA-304). The entire 5,000/month Argos Hobby quota is reserved for the built SvelteKit 3 PWA (pnpm build && pnpm preview).
  • Gate 1 (Stabilize) & Gate 2 (Fail-Closed @axe-core/playwright 4.14): auditAndCapture() sets prefers-reduced-motion: reduce, toggles .t-light / .t-dark, waits for document.fonts.ready and zero [aria-busy="true"] nodes, and runs AxeBuilder with wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa, and best-practice tags in both themes before argosScreenshot() is ever called.
  • Gate 3 (Landmarks & Keyboard Focus) & Gate 4 (argosScreenshot): Verifies visible <main>, single <h1>, and :focus-visible rings (MA-181), then captures full-page PNGs in both themes (threshold: 0.2) and the YAML accessibility tree on Light (ariaSnapshot: opts.theme === 'light').
2 · Tokenless OIDC upload, cloud merge-base matching & dual visual + ARIA diffing

Side-by-side pixel heatmaps and Git-style YAML accessibility tree diffs on every QA run

When Arun asks for QA and Playwright finishes on GitHub Actions, the Argos reporter uploads the screenshots and accessibility trees using GitHub's built-in identity—with no secret token stored anywhere. Argos automatically finds the matching baseline from main and compares every screen.

If a colour, chart line, or spacing shifted, Argos highlights the exact pixels in a side-by-side heatmap. And if a button label, heading level, or screen-reader role changed—even without changing a single pixel on screen—Argos shows a text diff of the accessibility tree right beside the picture.

  • Tokenless GitHub App OIDC (Zero Secrets): With the Argos GitHub App installed on gilipersonal/mypaisa-agent and Tokenless Authentication enabled, @argos-ci/playwright/reporter authenticates directly through the GitHub Actions check-run context—zero ARGOS_TOKEN in GitHub Secrets or AWS SSM.
  • Single-Pass CI Render (Saves ~45–60s/run): Unlike local git archive diffing that renders both main and HEAD on every run, GitHub Actions renders HEAD once per QA run. Argos resolves the Git merge-base commit on main in the cloud and supports automatic Playwright sharding (--shard=x/y) with zero merge scripts.
  • Dual Review Surface (`argos/visual` PR Check): Every screen pairs its 2x Retina PNG heatmap diff (Light & Dark) with its structured Playwright YAML .aria.yml tree diff, catching silent semantic regressions (missing aria-label, shifted heading hierarchy, dropped aria-live) that pass rule-based axe-core checks.
3 · Five engineering cost guardrails (MA-194, MA-269)

How five pipeline guardrails eliminate 89% of wasted snapshots and keep spend at £0.00/month

Argos CI's Hobby tier is free forever up to 5,000 snapshots a month, while the next tier up costs $100 a month. Without guardrails, running visual and accessibility snapshots on every commit across every file in the repository would burn 34,000 snapshots a month.

Five simple rules—running only when Arun asks (a manual run or a qa label), deduplicating the dark-mode accessibility tree, failing early on broken axe rules, cancelling superseded PR runs, and keeping local runs offline—keep usage at most 3,600 snapshots a month, safely inside the free tier.

  • Guardrail 1 (On request only, MA-303, MA-304) & Guardrail 2 (Light-Only ariaSnapshot): web-visual-a11y.yml triggers only on workflow_dispatch or a qa label, never on every PR, so monthly runs are at most the ~40 a per-PR trigger on web/** and cards/** would make (from ~85). Deduplicating ariaSnapshot: opts.theme === 'light' cuts per-screen items from 8 to 6 (saving 1,200 snapshots/month) because CSS custom properties in .t-dark never alter DOM roles or labels.
  • Guardrail 3 (Fail-Fast Axe + Offline Local Runs) & Guardrail 4 (cancel-in-progress: true): @axe-core/playwright aborts before argosScreenshot() on any violation; uploadToArgos: !!process.env.CI keeps laptop runs 100% local; and GitHub Actions concurrency cancels superseded PR pushes before the end-of-job reporter uploads.
  • Guardrail 5 (ubuntu-24.04-arm 1x + Cached Chromium): Uses ~2.0 mins/run (~80 billed GitHub mins/mo out of 2,000 free) with zero secrets and zero AWS cost.
