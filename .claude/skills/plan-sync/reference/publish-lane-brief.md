# Publish lane brief: send generated pages to Confluence, and read each back

Given to each publish lane (`SKILL.md`, "Publish in parallel"), with its list: a JSON file of
`{slug, id, title, recorded_version, file, bytes}` the coordinator writes from `confluence_docs.py pending` and
`docs/confluence.json`. `<scratch>` is the coordinator's scratch folder. First used on MA-301, 23 Nov 2026.

You publish pages that a script already generated. You change nothing in them, and you edit no file in any repo.

Atlassian site cloudId: `81c51173-bbea-4905-bbc5-1a880fa348bb`. Load the tools with ToolSearch first:
`select:mcp__atlassian__getConfluenceContent,mcp__atlassian__updateConfluenceContent,mcp__atlassian__executeRead`.

Your list is a JSON file of `{slug, id, title, recorded_version, file, bytes}`. For each page, in order:

1. **Check nobody edited it in Confluence.** `getConfluenceContent` with `content_id` = id, `detail: "summary"`.
   If its version number is higher than `recorded_version`, someone edited it there: do NOT publish it; note
   "edited in Confluence: live v<n>, recorded v<m>" and go to the next page.
2. **Get a snapshot token.** Use the `snapshotToken` the read returned; if the summary read has none, read it again
   with `detail: "full"`, `content_format: "html"`.
3. **Publish.** `updateConfluenceContent` with `contentId` = id, `title` = the list's title exactly,
   `body: {"format": "html", "value": <the file's content>}`, the snapshot token, and
   `versionMessage: "MA-<n>: <what changed> (generated by scripts/confluence_docs.py)"`.
   The value is the file at `file`, byte for byte: read it with the Read tool (or `cat`) and send exactly that. Do
   not reformat, trim, escape differently, or "fix" anything: a later check compares the page with the file, and any
   difference fails it. The tool's description suggests reading the content format guide and the space's
   instructions first; you may read them once, but the body is generated storage HTML that is already correct, so it
   is sent as it is whatever they say. Do not pass `contentWidth`. On `snapshot_stale`, read again and retry once.
4. **Read it back.** `getConfluenceContent` with `content_id` = id, `detail: "full"`, `content_format: "html"`.
   Save the WHOLE reply, the JSON exactly as it came (not just its body), to
   `<scratch>/readback/<slug>.json`.
   If the harness saved the tool's output to a file (it says "Output too large… saved to <path>"), copy that file with
   `cp` instead of retyping it; otherwise write the reply with the Write tool, verbatim. Check the saved file parses
   as JSON (`python3 -c "import json,sys; json.load(open(sys.argv[1]))" <file>`), and that its body.value starts and
   ends like the file you sent.
5. Note the page's new version number (from the update's reply or the read-back's `metadata.version.number`).

Never delete or archive a page or attachment. Run no other Atlassian write. Do not run any repo script.

Reply with one line per page: `slug | id | new version | readback file | ok`, or `slug | id | SKIPPED or ERROR: why`.
